# ZMK Config for Bifrost

ZMK firmware configuration for the Bifrost BLE split keyboard, generated with
**Smidr**.

The left half is the split central and provides the USB connection. The right
half is the peripheral and includes support for a PMW3610 pointing device.

## Repository Structure

- `config/bifrost.keymap`: Shared keymap and layer definitions generated by Smidr.
- `config/bifrost_left.keymap` and `config/bifrost_right.keymap`: Per-board entry
  points that include the shared keymap.
- `boards/hringbord/bifrost.dtsi`: Matrix transform shared by both halves.
- `boards/hringbord/bifrost-layouts.dtsi`: Shared physical layout for ZMK Studio.
- `boards/hringbord/bifrost_left/`: Left board definition and central-side settings.
- `boards/hringbord/bifrost_right/`: Right board definition, peripheral-side settings,
  and pointing-device configuration.
- `config/west.yml`: ZMK workspace manifest.
- `zephyr/module.yml`: Makes the custom board definitions available to Zephyr.
- `build.yaml`: GitHub Actions build matrix for both halves.

## Build

### Liki layer integration

The left (central) firmware enables `CONFIG_ZMK_LIKI` from the external
[`zmk-feature-liki`](https://github.com/hringdrifi/zmk-feature-liki) module.
`config/west.yml` pins the module to a specific commit. It notifies Liki on
Android/iPhone of the highest active layer over BLE, independently of Studio.
Rebuild and flash the left half to enable it; the right half needs no change.
Physical layout and key labels still come from Studio when available.

This repository is already configured as a complete ZMK user-config repository;
its directories do not need to be copied into another repository.

1. Fork or clone this repository.
2. Edit `config/bifrost.keymap` as needed.
3. Commit and push the changes to GitHub.
4. Open the repository's **Actions** tab and select the latest successful
   **Build ZMK firmware** run.
5. Download and extract the firmware artifacts. Put each half into its UF2
   bootloader mode, then copy the matching `.uf2` file to the USB mass-storage
   drive that appears.

The build matrix produces firmware for both custom boards:

```yaml
include:
  - board: bifrost_left
    snippet: studio-rpc-usb-uart
    cmake-args: -DCONFIG_ZMK_STUDIO=y
    artifact-name: bifrost_left_studio
  - board: bifrost_right
```

Both board definitions generate UF2 output and target the application partition
at `0x26000`, leaving the installed Adafruit nRF52 UF2 bootloader intact.

## US-style symbols on Windows Japanese layout

The keymap on the `codex/jis-host-us-layout` branch targets Windows with its
hardware keyboard layout set to Japanese (106/109 keys). It remaps the existing
base and LOWER symbol positions so they type their intended US-layout characters
without changing the Windows layout setting. This mapping is specific to the
Japanese host layout; other host layouts will produce different symbols.
After flashing, use **Restore Stock Settings** in ZMK Studio if it has a saved
keymap, then check symbols including `\\`, `|`, `_`, `:`, brackets, and quotes.

Bluetooth identities, pairing keys, and Studio settings use the NVS storage
partition at `0xEC000`--`0xF3FFF`. Both boards enable `CONFIG_FLASH_MAP` so that
`CONFIG_SETTINGS_NVS` is selected instead of the non-persistent settings backend.
The application partition ends at `0xEC000`; the UF2 bootloader starts at `0xF4000`.
When updating from firmware that did not retain Bluetooth settings, flash both
halves, remove the old Bifrost pairing on the host once, and pair again. Wait at
least two seconds after pairing before restarting either half, allowing the
delayed Bluetooth settings write to finish.

If the right half stops connecting after migrating the settings partition,
reset the pairing on both halves. Back up any Studio keymap first: this erases
all saved settings, including Bluetooth bonds and Studio changes.
Flash `bifrost_left_settings_reset.uf2` to the left and
`bifrost_right_settings_reset.uf2` to the right, letting each reset image boot.
Reset both halves before flashing either normal image, so an old firmware
identity cannot be bonded during the procedure. Then flash
`bifrost_left_studio.uf2` and `bifrost_right-zmk.uf2`, power both halves off and on
together, and remove/re-pair Bifrost on the host once.

## ZMK Studio

ZMK Studio is enabled on the left (central) half. Flash both artifacts, connect
the left half over USB, then hold either thumb layer key and press the other
(`LOWER` + `RAISE`) to unlock editing. Then open
[ZMK Studio](https://zmk.studio/).

The physical layout is defined in `boards/hringbord/bifrost-layouts.dtsi`.
Studio stores keymap changes on the keyboard, so later `.keymap` changes require
**Restore Stock Settings** in Studio before they take effect.

## Trackball

The right half uses the badjeff PMW3610 driver pinned in `config/west.yml`.
It runs at 1000 CPI with X inverted and Y unchanged. SPI is limited to 125 kHz,
and the build applies a 15 us chip-select delay patch to meet sensor timing.
The force-awake setting follows ZMK activity changes; a 1 second startup delay
allows the sensor power to settle before initialization.

The trackball moves the pointer on the base layer. The 1000 CPI sensor setting
reduces both pointer and scroll movement by about 17% compared with 1200 CPI.
While `LOWER` is held, its
X/Y movement is converted to horizontal/vertical scrolling at 1/16 sensitivity;
the right-hand `N`, `M`, and comma positions act as left, middle, and right
mouse buttons.

Pointer movement automatically enables the `MOUSE` layer (layer 3): `J` is left
click, `K` is middle click, and `L` is right click. It turns off after 1200 ms
without trackball input, or when another keyboard position is pressed. The
three click positions are excluded from immediate cancellation. Activation
requires 200 ms without keyboard input to avoid switching layers while typing.
`LOWER` scrolling and `RAISE` navigation take precedence over auto activation.
If Studio has saved an older keymap, set the layer 3 `J`/`K`/`L` bindings to
left/middle/right click in Studio, or back up the keymap before using **Restore
Stock Settings** to load the firmware defaults.

## Split Matrix

Both custom board DTS files include the full matrix transform from
`boards/hringbord/bifrost.dtsi`. The right board applies `col-offset = <24>` so
local right-side matrix events map into the right side of the shared transform.
